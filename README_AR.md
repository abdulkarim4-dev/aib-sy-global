# AIB Real App — النسخة المتصلة بقاعدة بيانات مركزية

هذه حزمة تطبيق ويب متجاوب للهاتف والكمبيوتر، بواجهة عربية/إنجليزية وخادم API وقاعدة بيانات PostgreSQL. الواجهة الجديدة تتصل بالخادم مباشرة ولا تعتمد على `localStorage` لحفظ السجلات أو المستخدمين.

## الوظائف الموجودة في هذه الحزمة

- تسجيل دخول مركزي بكلمات مرور مجزأة باستخدام Argon2، ورموز جلسات JWT قصيرة العمر.
- إنشاء حساب المدير الأول من متغيرات البيئة عند أول تشغيل لقاعدة بيانات فارغة.
- قفل حساب المستخدم خمس دقائق بعد ثلاث محاولات كلمة مرور خاطئة.
- أدوار مدير وموظف؛ فحص الصلاحيات على الخادم وليس على الواجهة فقط.
- الموظف يضيف سجلات وحركات نقدية، ويرسل طلب تعديل/حذف؛ المدير وحده ينفذ التعديل أو الحذف ويعتمد الطلبات.
- أقسام: ودائع الأمانة، المشتريات، مبيع الأمانة، المبيع المباشر، الصيانة والتصليح.
- عملتا USD وSYP، وصناديق نقدية وحركاتها.
- سجل تدقيق للأحداث الإدارية، وواجهة لإدارة المستخدمين وطلبات التعديل والحذف.
- طباعة مستند للسجل، وإظهار رقم الشاسيه فقط عندما تكون قيمته مدخلة.
- نشر عبر Caddy للحصول على HTTPS تلقائياً بعد توجيه الدومين إلى الخادم.
- نسخ احتياطي واستعادة لقاعدة PostgreSQL عبر scripts.

## ما لا يزال يحتاج اعتماداً قبل الاستخدام المحاسبي التجاري

- هذه أول واجهة متصلة، وليست نقلاً كاملاً لكل تفاصيل شاشات النسخة المحلية v11. نموذج السجل الحالي عام، ويحتاج استكمال حقول كل قسم ومطابقة قواعد الصناديق والفواتير مع ملف Excel الأصلي.
- لا يتم ترحيل بيانات `localStorage` القديمة تلقائياً. يجب تصدير بيانات النسخة المحلية ومراجعة مطابقة الحقول والأرصدة قبل استيرادها.
- ترقيم الفواتير الحالي يُدخل في السجل؛ لم يتم بعد تنفيذ عدادات ذرية منفصلة A/B/C/D على مستوى قاعدة البيانات.
- حركات الصندوق تسجل بشكل مستقل؛ لا تُرحّل المشتريات والمبيعات تلقائياً إلى الصناديق قبل اعتماد قواعد الترحيل حتى لا تنشأ أرصدة خاطئة أو حركات مكررة.
- لا تعتمد على النسخة الحالية قبل اختبار حالات المحاسبة الفعلية، النسخ الاحتياطي والاستعادة، وتدقيق الصلاحيات مع حسابات تجريبية.

## متطلبات النشر على الإنترنت

تحتاج إلى خادم Linux (Ubuntu 24.04 LTS موصى به) بعنوان IP عام، واسم نطاق تملكه، وإمكانية فتح TCP 80 و443. يجب توجيه سجل DNS من نوع A إلى عنوان الخادم. لا تضع قاعدة البيانات على الإنترنت ولا تفتح منفذ PostgreSQL للعامة.

### 1) نقل الحزمة إلى الخادم

ارفع ملف ZIP إلى الخادم ثم فك ضغطه، وادخل مجلد `AIB_Real_App`.

### 2) إعداد الأسرار

```bash
cp .env.example .env
nano .env
```

غيّر جميع القيم:
- `AIB_DOMAIN`: الدومين الحقيقي مثل `accounting.your-domain.com`.
- `DB_PASSWORD`: كلمة عشوائية طويلة من أحرف وأرقام (تجنب `@:/` لأن القيمة تدخل في رابط اتصال PostgreSQL).
- `JWT_SECRET`: سر عشوائي قوي لا يقل عن 64 حرفاً.
- `OWNER_PASSWORD`: كلمة مرور مدير فريدة لا تقل عن 16 حرفاً.

يمكن توليد قيم عشوائية على Linux:

```bash
openssl rand -hex 32
openssl rand -hex 48
```

لا ترسل ملف `.env` أو كلمات المرور في محادثة عامة. احفظ نسخة آمنة منها خارج مجلد النشر.

### 3) تشغيل الخدمات

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f api
```

بعد ضبط DNS وفتح المنافذ، افتح `https://YOUR_DOMAIN`. Caddy يطلب شهادة TLS تلقائياً. اختبار صحة الخادم: `https://YOUR_DOMAIN/health`.

### 4) بيانات المدير الأول

- اسم المستخدم: القيمة الموجودة في `OWNER_USERNAME` (الافتراضي `abdulkarim`).
- كلمة المرور: القيمة التي وضعتها بنفسك في `OWNER_PASSWORD`.

يُنشأ المدير عند أول تشغيل فقط إذا لم يكن اسم المستخدم موجوداً مسبقاً. تغيير `.env` لاحقاً لا يغير كلمة مرور مستخدم موجود؛ يجب تنفيذ إجراء تغيير كلمة المرور الإداري قبل الإنتاج (غير متوفر في هذه النسخة الأولية).

### 5) النسخ الاحتياطي

```bash
./scripts/backup.sh
```

استعادة نسخة احتياطية (استبدال البيانات الحالية):

```bash
CONFIRM_RESTORE=YES ./scripts/restore.sh backups/aib-YYYYMMDDTHHMMSSZ.sql.gz
```

انقل النسخ الاحتياطية دورياً إلى مكان آخر مشفر؛ وجودها على الخادم نفسه لا يحمي من فقدان الخادم.

## ملاحظات أمنية

- الواجهة تحفظ رمز الجلسة في ذاكرة الصفحة فقط، لذلك يلزم تسجيل الدخول مجدداً بعد إعادة تحميلها.
- صلاحية الرمز الافتراضية 30 دقيقة.
- الحماية لا تزال بحاجة إلى اختبار اختراق ومراجعة أمنية، وحدود محاولات حسب IP، وسياسة استعادة كلمة المرور، وإدارة جلسات قابلة للإبطال قبل الاستخدام الحساس.
- لا تضع بيانات عملاء حقيقية قبل إكمال مراجعة أمنية ومحاسبية مستقلة.
